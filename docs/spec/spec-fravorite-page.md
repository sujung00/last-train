# Feature Spec: 즐겨찾기 페이지

> 작성일: 2026-07-08
> 상태: 구현 완료 (2026-07-08, T-001~T-007)
> 대상 화면: FavoritePage (/favorites)

---

## 1. 배경

메인 홈에서 즐겨찾기 칩을 통해 빠른 조회가 가능하지만,
즐겨찾기 목록을 관리(추가/편집/삭제)하는 전용 화면이 없는 상태다.
FavoritePage는 즐겨찾기 목록의 중심 화면으로, 빠른 막차 조회와 목록 관리를 담당한다.

---

## 2. 목표

- 즐겨찾기 목록을 한눈에 확인할 수 있다.
- "조회 →" 탭 한 번으로 현재 위치 → 해당 목적지 막차를 바로 조회할 수 있다.
- 이름/이모지를 편집하거나 삭제할 수 있다.
- 새 목적지를 추가할 수 있다.

---

## 3. 비목표

- 즐겨찾기 순서 변경(드래그 앤 드롭)은 이번 범위에 포함하지 않는다.
- 알림 구독 기능은 이번 범위에 포함하지 않는다.

---

## 4. 사용자

| 사용자 | 니즈 | 제약 |
|--------|------|------|
| 로그인 사용자 | 자주 가는 목적지를 저장하고 빠르게 막차 조회하고 싶다 | 본인 즐겨찾기만 조회/수정 가능 |
| 비로그인 사용자 | - | 로그인 페이지로 이동 |

---

## 5. 기능 요구사항

| ID | 요구사항 |
|----|---------|
| FR-001 | GET /api/v1/favorites로 즐겨찾기 목록을 조회해 표시해야 한다 |
| FR-002 | 각 항목에 이모지, 이름, 주소를 표시해야 한다 |
| FR-003 | "조회 →" 탭 시 현재 GPS 위치를 출발지로, 해당 목적지를 도착지로 설정해 막차 조회 결과(/result)로 이동해야 한다 |
| FR-004 | "편집" 탭 시 이름/이모지 편집 모달을 표시해야 한다 |
| FR-005 | 편집 모달에서 이름과 이모지를 수정할 수 있어야 한다 |
| FR-006 | 편집 모달에서 즐겨찾기를 삭제할 수 있어야 한다 |
| FR-007 | 헤더의 "+ 추가" 또는 하단의 "+ 목적지 추가" 버튼 탭 시 PlaceSearchModal을 재활용해 장소를 검색할 수 있어야 한다 |
| FR-008 | 장소 선택 → 이모지 선택(EmojiSelectorModal 재활용) 완료 시 즐겨찾기에 추가되고 목록이 갱신되어야 한다 |

---

## 6. 수용 기준 (EARS 스타일)

- AC-001: `WHEN FavoritePage에 진입하면, THE 시스템 SHALL GET /api/v1/favorites를 호출해 목록을 표시한다.`
- AC-002: `WHEN 비로그인 사용자가 /favorites에 접근하면, THE 시스템 SHALL 페이지 안에서 "로그인하면 즐겨찾기를 사용할 수 있어요" 안내와 [로그인하기] 버튼을 표시한다.`
- AC-003: `WHEN "조회 →" 버튼을 탭하면, THE 시스템 SHALL GPS 현재 위치를 출발지로 설정하고 해당 즐겨찾기를 도착지로 설정해 막차 조회 API를 호출한 후 /result로 이동한다.`
- AC-004: `WHEN "편집" 버튼을 탭하면, THE 시스템 SHALL 이름/이모지 편집 모달을 표시한다.`
- AC-005: `WHEN 편집 모달에서 저장을 탭하면, THE 시스템 SHALL PATCH /api/v1/favorites/{id}를 호출하고 목록을 갱신한다. 요청 형식: { name, emoji }`
- AC-006: `WHEN 편집 모달에서 삭제를 탭하면, THE 시스템 SHALL DELETE /api/v1/favorites/{id}를 호출하고 목록에서 제거한다.`
- AC-007: `WHEN "+ 추가" 또는 "+ 목적지 추가"를 탭하면, THE 시스템 SHALL PlaceSearchModal을 표시한다.`
- AC-008: `WHEN 장소 선택 후 이모지 선택을 완료하면, THE 시스템 SHALL POST /api/v1/favorites를 호출하고 목록을 갱신한다.`

## 7. 엣지 케이스

| ID | 상황 | 처리 방식 |
|----|------|---------|
| EC-001 | 즐겨찾기 목록이 비어있는 경우 | "아직 즐겨찾기한 목적지가 없어요" + "+ 목적지 추가" 버튼 표시 |
| EC-002 | 비로그인 상태로 접근 | /favorites 페이지 안에서 로그인 유도 화면 표시 ("로그인하면 즐겨찾기를 사용할 수 있어요" + [로그인하기] 버튼 → /login 이동) |
| EC-003 | "조회 →" 탭 시 GPS 권한 없는 경우 | 메인 홈(/로 이동 후 EC-001(GPS 거부) 처리 위임 |
| EC-004 | 편집/삭제 API 실패 | 에러 배너 표시 (기존 배너 스타일 적용) |
| EC-005 | 목록 조회 API 실패 | "목록을 불러오지 못했어요. 다시 시도해주세요" 에러 배너 표시 |

---

## 8. 비기능 요구사항

- 기존 컴포넌트 재활용: PlaceSearchModal, EmojiSelectorModal
- 기존 axios 설정(api/axios.js) 사용
- 기존 코드 스타일 (Tailwind CSS, dark navy #1a1a2e) 유지
- 로딩 중 스피너 표시

---

## 9. 연관 API

| 용도 | 메서드 | 경로 |
|------|--------|------|
| 목록 조회 | GET | /api/v1/favorites |
| 즐겨찾기 추가 | POST | /api/v1/favorites |
| 즐겨찾기 편집 | PATCH | /api/v1/favorites/{id} (name, emoji만) |
| 즐겨찾기 삭제 | DELETE | /api/v1/favorites/{id} |
| 막차 조회 | POST | /api/v1/routes/last-train |

# Feature Spec: 막차 알리미 메인 화면

> 작성일: 2026-06-30  
> 상태: 구현 완료 (2026-06-30, T-001~T-012)  
> 대상 화면: 메인 홈 / 장소 검색 / 막차 조회 결과

---

## 1. 배경

막차 알리미의 핵심 흐름은 "출발지 + 도착지 입력 → 막차 조회 → 결과 확인"이다.  
백엔드 API는 완성된 상태이며, 이 스펙은 프론트엔드 3개 화면 구현을 위한 기준 문서다.

---

## 2. 목표

- 사용자가 출발지/도착지를 입력해 막차 시각과 출발 마감 시각을 확인할 수 있다.
- 즐겨찾기 목적지를 탭 한 번으로 빠르게 조회할 수 있다.
- 최근 검색 기록을 통해 반복 조회를 편하게 할 수 있다.
- 결과 화면에서 바로 즐겨찾기 등록을 할 수 있다.

---

## 3. 비목표

- 알림 구독 기능은 이번 화면 스펙에 포함하지 않는다. (별도 스펙으로 분리)
- 마이 페이지 화면은 이번 스펙에 포함하지 않는다.
- 즐겨찾기 목록 관리(수정/삭제)는 즐겨찾기 탭 스펙으로 분리한다.

---

## 4. 화면 구성

| 화면 | 설명 |
|------|------|
| 메인 홈 | 출발지/도착지 입력, 즐겨찾기 칩, 최근 검색, 막차 조회 버튼 |
| 장소 검색 | 출발지/도착지 공통으로 사용하는 카카오 장소 검색 모달 |
| 막차 조회 결과 | 추천/대안 경로 카드, 남은 시간 배너, 즐겨찾기 추가 버튼 |

---

## 5. 기능 요구사항

| ID | 요구사항 |
|----|---------|
| FR-001 | 앱 진입 시 출발지는 GPS 현재 위치로 자동 설정되어야 한다 |
| FR-002 | 출발지는 "변경" 버튼 탭 시 장소 검색 화면으로 전환되어 직접 입력할 수 있어야 한다 |
| FR-003 | 도착지 입력창 탭 시 장소 검색 화면으로 전환되어야 한다 |
| FR-004 | 장소 검색은 카카오 Local API를 호출해 결과를 실시간으로 표시해야 한다 |
| FR-005 | 출발지 검색 화면과 도착지 검색 화면은 동일한 장소 검색 컴포넌트를 재사용해야 한다 |
| FR-006 | 출발지를 직접 검색해서 선택한 경우 GPS 자동 위치 표시 대신 선택한 장소명으로 교체되어야 한다 |
| FR-007 | 즐겨찾기 목적지 칩 탭 시 해당 장소가 도착지로 자동 입력되어야 한다 |
| FR-008 | 최근 검색 목록은 "출발지 → 도착지" 형식으로 localStorage 기반 최대 5개까지 표시해야 한다 |
| FR-009 | 출발지 + 도착지가 모두 입력된 상태에서만 막차 조회 버튼이 활성화되어야 한다 |
| FR-010 | 막차 조회 결과 화면에 추천 경로와 대안 경로를 최대 5개까지 표시해야 한다 |
| FR-011 | 결과 화면 상단에 막차까지 남은 분(分)을 표시해야 한다 |
| FR-012 | 결과 화면에서 "즐겨찾기 추가" 버튼으로 해당 목적지를 즐겨찾기에 등록할 수 있어야 한다 |
| FR-013 | 즐겨찾기 등록 시 사용자가 직접 이모지를 선택해 설정할 수 있어야 한다 |

---

## 6. 수용 기준 (EARS 스타일)

- AC-001: `WHEN 앱이 처음 로드되면, THE 시스템 SHALL GPS 위치를 요청하고 출발지 입력창에 "현재 위치 (GPS 자동)"으로 표시한다.`
- AC-002: `WHEN 출발지 변경 버튼 또는 도착지 입력창을 탭하면, THE 시스템 SHALL 장소 검색 화면으로 전환한다.`
- AC-003: `WHEN 장소 검색창에 텍스트를 입력하면, THE 시스템 SHALL 카카오 Local API를 호출해 결과 목록을 표시한다.`
- AC-004: `WHEN 검색 결과에서 장소를 선택하면, THE 시스템 SHALL 해당 장소를 출발지 또는 도착지에 설정하고 메인 홈으로 돌아간다.`
- AC-005: `WHEN 즐겨찾기 칩을 탭하면, THE 시스템 SHALL 해당 장소를 도착지로 자동 입력한다.`
- AC-006: `WHEN 출발지와 도착지가 모두 입력되면, THE 시스템 SHALL 막차 조회 버튼을 활성화한다.`
- AC-007: `WHEN 막차 조회 버튼을 탭하면, THE 시스템 SHALL POST /api/v1/routes/last-train을 호출하고 결과 화면으로 전환한다.`
- AC-008: `WHEN 결과 화면이 로드되면, THE 시스템 SHALL 막차까지 남은 시간을 분 단위로 표시한다.`
- AC-009: `IF 비로그인 사용자가 즐겨찾기 추가 버튼을 탭하면, THE 시스템 SHALL 로그인 페이지로 이동한다.`
- AC-010: `THE 시스템 SHALL 막차 조회 성공 시 해당 경로를 localStorage 최근 검색에 저장한다.`

## 7. 엣지 케이스

| ID | 상황 | 처리 방식 |
|----|------|---------|
| EC-001 | GPS 권한 거부 | "위치 권한이 없어요. 출발지를 직접 입력해주세요" 안내 후 수동 입력 유도 |
| EC-002 | 장소 검색 결과 없음 | "검색 결과가 없어요" 빈 상태 표시 |
| EC-003 | 이미 막차가 지난 경우 | "오늘 막차는 종료됐어요" 안내 |
| EC-004 | ODsay API 오류 | "잠시 후 다시 시도해주세요" 에러 표시 |
| EC-005 | 비로그인 즐겨찾기 추가 탭 | 로그인 페이지로 이동 |
| EC-006 | 이미 즐겨찾기 등록된 목적지 | 버튼 텍스트를 "즐겨찾기 등록됨"으로 변경, 비활성화 |
| EC-007 | 출발지와 도착지가 동일 | (MainPage) "출발지와 도착지가 같아요" 안내 후 조회 막기 / (ResultPage) 동일 상태로 결과 화면에 도달한 경우 배너 또는 alert로 동일 안내 문구 표시 |

---

## 8. 비기능 요구사항

- **성능**: 장소 검색 결과는 입력 후 300ms 디바운스 적용
- **UX**: 막차 조회 중 로딩 스피너 표시
- **저장**: 최근 검색은 localStorage에 저장 (서버 불필요)
- **인증**: 즐겨찾기 추가는 로그인 필요, 조회는 비로그인도 가능

---

## 9. 연관 API

| 용도 | 메서드 | 경로 |
|------|--------|------|
| 막차 조회 | POST | /api/v1/routes/last-train |
| 즐겨찾기 등록 | POST | /api/v1/favorites |
| 즐겨찾기 목록 조회 | GET | /api/v1/favorites |
| 장소 검색 | GET | 카카오 Local API (프론트 직접 호출) |

## 10. 열린 질문

- Q1: ~~최근 검색 표시 형식은 "출발지 → 도착지"인가, 도착지만인가?~~ → **해결**: "출발지 → 도착지" 전체 표시 (FR-008)
- Q2: ~~대안 경로는 최대 몇 개까지 표시하는가?~~ → **해결**: 최대 5개까지 표시 (FR-010, API 자체 제한 없음, 프론트에서 5개로 슬라이싱)
- Q3: ~~즐겨찾기 칩에 이모지는 사용자가 직접 설정하는가?~~ → **해결**: 사용자가 직접 설정 (FR-013)

## 11. 검증 계획

- GPS 권한 허용/거부 두 경로 모두 출발지 입력창이 정상 표시되는지 테스트한다.
- 출발지/도착지 검색에서 동일한 장소 검색 컴포넌트가 재사용되는지 확인한다.
- 출발지와 도착지를 동일 장소로 선택했을 때 조회가 막히는지 테스트한다(EC-007).
- 막차 조회 버튼이 출발지/도착지 입력 전에는 비활성화 상태인지 확인한다(AC-006).
- 결과 화면에서 추천/대안 경로가 최대 5개로 제한되는지 확인한다(FR-010).
- 비로그인 상태에서 즐겨찾기 추가 시 로그인 페이지로 이동하는지 테스트한다(EC-005).
- 이미 즐겨찾기로 등록된 목적지를 재조회했을 때 버튼이 "등록됨" 상태로 표시되는지 확인한다(EC-006).
- 막차 조회 성공 시 최근 검색에 "출발지 → 도착지" 형식으로 저장되는지 확인한다(AC-010, FR-008).
- ODsay API 오류, 막차 종료 등 에러 케이스에서 안내 문구가 올바르게 노출되는지 확인한다(EC-003, EC-004).
- **리뷰 기준**: 구현 결과가 FR-001~FR-013을 모두 만족하는지, 스펙에 없는 임의 기능이 추가되지 않았는지 diff 기준으로 검토한다.
- **배포 후 확인 지표**: 장소 검색 API 호출 실패율, 막차 조회 API 응답 시간, 즐겨찾기 추가 전환율.
